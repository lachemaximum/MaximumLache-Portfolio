# ゲーム系 楽天アフィリブログ 運用ルール

このフォルダは、はてなブログにゲーム攻略記事と周辺機器の比較記事を毎朝自動で作り、予約投稿するためのもの。
毎回新しいセッションで起動するため、手順・設定・進行状況はすべてこのフォルダ内のファイルに書いてある。記憶に頼らず、必ずファイルを読んでから動くこと。

## 現在の運用モード

**お試し**

- お試し：記事を3本作り、はてなブログに **下書き** として保存して終わる（`post_hatena.py --draft`）。本人が確認する
- 本運用：本人の OK が出たら、この行を「本運用」に書き換える。以降は予約投稿する

## 1日の実行手順（毎朝4時）

作業はすべて `game-blog/` をカレントディレクトリにして行う。日付は日本時間（JST）で数える。

1. **テーマ決定**
   - `logs/theme_progress.md` と `config/themes.md` を読み、今日のテーマを1つ決める
   - 原則は曜日割り。セール時期（`config/themes.md` 参照）はセールのまとめを優先する
   - `logs/post_log.md` を見て、今日の分がすでに投稿済みなら、未投稿の枠だけを作る（二重投稿しない）
2. **商品データ取得**
   - `python3 scripts/fetch_products.py --theme "<テーマ名>" --keyword "<検索語>" [--keyword ...]`
   - `data/products/<日付>.json` に保存される。直近に使った商品は自動で除外される
3. **記事3本の企画**
   - `config/article-types.md` の3つの型（攻略・比較・選び方）で、検索意図をずらす
   - 狙うキーワードは `config/themes.md` を使う。同じキーワードを2本で狙わない
4. **記事生成**
   - `drafts/<日付>/1.md`（攻略・8時）、`2.md`（比較・12時）、`3.md`（選び方・18時）に書く
   - 書式は `config/article-types.md` の「下書きファイルの書式」に従う
   - 比較表とリンクは手で書かず、`python3 scripts/build_parts.py --date <日付> --codes <itemCode,...>` の出力を貼る
   - 3本は内部リンクで相互に結ぶ（まだ URL がない記事は、後日のリンク追加を `logs/theme_progress.md` にメモする）
5. **事実確認**
   - `fact-checker` サブエージェントに、各記事のゲーム仕様と商品スペックを確認させる
   - 指摘をすべて直したら、その記事のフロントマターを `fact_check: ok` にする
6. **公開前チェック**
   - `python3 scripts/check_article.py --date <日付> --log`
   - 落ちた記事は投稿しない。理由は `logs/post_log.md` に残る。直せるものは直して再チェックしてよい
7. **投稿**
   - お試し：`python3 scripts/post_hatena.py --date <日付> --draft`
   - 本運用：`python3 scripts/post_hatena.py --date <日付>`（8時・12時・18時の予約投稿）
   - スクリプトは投稿前にもう一度チェックし、投稿済みの枠は飛ばす
8. **記録**
   - `logs/post_log.md` と `data/used_products.json` はスクリプトが更新する
   - `logs/theme_progress.md` の「使用済みテーマ」と「次のテーマ」を手で更新する
   - 最後に、変更をすべてコミットしてプッシュする（次のセッションは、プッシュされたファイルしか見られない）

## 守るルール

- **PR表記**：すべての記事の冒頭に入れる
- **効果の断定を避ける**：「このキーボードで勝てる」ではなく、「◯◯を助けてくれる機能」と書く
- **価格を書かない**：価格は変動するので、リンク先で確認してもらう。予算帯（「1万円台」など）はよい
- **事実確認を必ず通す**：ゲームの仕様と商品スペックが対象。攻略情報は公式情報と実プレイをもとに書き、他サイトの丸写しはしない
- **記事の重複を避ける**：1日3本は検索意図をずらし、同じキーワードを狙わない
- **公開ペースを守る**：最初の1〜2週間は1日3本で使用量を見て、必要なら2本に落とす
- **秘密情報**：楽天とはてなのキーは `.env`（Git管理から除外）に置き、このファイルや記事ファイルには書かない。実行環境側にも同じ環境変数を設定する
- **削除はしない**：記事の削除や上書きは自動化しない。必要なときは、ブラウザから手動で行う

## 失敗時の動き

- 3本中1本が落ちても、通過した記事は投稿する
- 途中で止まったら、`logs/post_log.md` を見て、投稿済みの枠を飛ばしてやり直す
- 同じ日・同じ枠の記事を二度投稿しない
- API に接続できないなど、続けられないときは、何が起きたかを `logs/post_log.md` の末尾に書き、コミットして終わる
